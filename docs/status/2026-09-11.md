## Effective GitHub Actions runner provenance

The golden builder verifies GitHub's published SHA-256 for the selected `actions/runner` release and retains its `tag`/asset hash. Because repository JIT configuration does not expose a supported `disableupdate` input, authoritative jobs additionally verify the effective runner binary at execution time.

An upstream audit found that querying `run.sh --version` was not a reliable evidence interface: official `run.sh` delegates through `run-helper.sh`, which can emit wrapper messages around `Runner.Listener`. The correct interface is the runner listener itself, whose upstream command parser handles `--version` and `--commit` before normal run mode.

- `cd736c8ac528cec4aec6e958ab21b0130226c4c5`: initial runtime provenance checker; policy `34662845870` PASS, but later upstream audit identified the `run.sh` evidence ambiguity before authoritative KVM execution.

Policy `34665058812` **PASS**; hosted scope `34665058807` PASS with `sbuild` skipped.

## Golden-image provenance gate before JIT

The public JIT entrypoint validates the golden image before any JIT orchestration starts. `scripts/check-golden-image-provenance.sh` requires exactly one valid value for `golden_image_sha256`, `source_image_sha256`, `source_commit`, `source_checkout_removed=yes` and `source_image_provenance_verified=yes`.

It recalculates the golden image SHA-256 and fails closed on ambiguity, tampering, missing signed-source proof, missing source cleanup or invalid source commit evidence. `scripts/run-kvm-jit-gate.sh` is the public entrypoint; after this gate succeeds it delegates argument-preservingly to `scripts/run-kvm-jit-gate-core.sh`, which retains the serialized/JIT/exact-run-bound orchestration.

## Decisions

- Ubuntu is platform authority; KDE upstream stable is desktop authority. Provider and authority remain separate.
- KDE's selected Qt series controls the provider requirement. Ubuntu Qt may be reused only through SupraLINUX gates; provider preflight does not transfer authority to Ubuntu.
- SupraLINUX remains mutable `.deb`/APT/dpkg.
- Hosted GitHub runners remain non-authoritative preflight.
- Authoritative jobs run in disposable Ubuntu 26.04 KVM/JIT guests.
- Nested KVM is a runtime requirement, not a label assumption.
- `autopkgtest/QEMU` must use the KVM-only QEMU wrapper; TCG fallback cannot count as authoritative PASS.
- JIT jobs are serialized on the host, reject fork PRs, and bind evidence to one new workflow run ID for the exact PR head SHA.
- Golden source images must pass both fetch-time Ubuntu signature verification and use-time cryptographic re-verification before use.
- A golden image is ineligible for JIT unless its current bytes match provenance and provenance proves signed-source re-verification plus source-checkout cleanup.
- Effective Actions runner version/commit are checked at authoritative runtime through `bin/Runner.Listener`; version drift from the verified golden runner release requires golden refresh.
- Repository Policy requires Bash syntax, ShellCheck, QEMU-wrapper test, signed source-image test, effective-runner test, golden-provenance test, architecture invariants, Qt-provider invariants and live Qt verification.
- DAG states remain `PASS`, `FAIL`, `BLOCKED`; `BLOCKED` is not `FAIL`.
