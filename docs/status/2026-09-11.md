## Decisions

- Ubuntu 26.04 LTS is the base platform; KDE upstream stable is authoritative for the desktop stack.
- Qt provider selection follows KDE's selected requirement profile.
- SupraLINUX remains a mutable `.deb`/APT/dpkg system.
- GitHub-hosted Ubuntu 26.04 is a **non-authoritative preflight lane**.
- Authoritative build/test execution occurs inside disposable self-hosted **KVM virtual machines running Ubuntu 26.04**.
- The authoritative VM is registered with GitHub through a per-VM JIT configuration; persistent GitHub runner credentials are not baked into the golden image.
- Pre-merge self-hosted gates use controlled PR labels and refuse fork PRs.
- The authoritative runner VM uses a fresh `sbuild/unshare` environment for package builds.
- Authoritative package/system tests use `autopkgtest/QEMU` inside the KVM runner VM; nested KVM is part of the certification contract.
- Build artifacts and hashes are captured immediately after successful build gates, before later test gates.
- Build graph states are `PASS`, `FAIL` and `BLOCKED`; `BLOCKED` is distinct from `FAIL`.

## Inference

Ubuntu Qt 6.10.2 remains a strong reuse candidate for the current Plasma 6.7 profile, but version-line agreement is not a certification result.

Attempt 2 showed that `sbuild/unshare` works on the hosted Ubuntu 26.04 runner while `autopkgtest/unshare` failed at a separate testbed-infrastructure layer. The later hosted PASS independently confirms the clean `sbuild/unshare` path with preserved binary evidence.

The repository now has enough orchestration to attempt authoritative certification without merging the Draft PR first. This is an implementation conclusion, not evidence that KVM/JIT execution itself works; only a real host run can establish that.

## Implementation now available

- `.github/workflows/runner-contract.yml` checks Ubuntu 26.04, KVM virtualization, `/dev/kvm`, QEMU/KVM capability, toolchain and prepared test image.
- `.github/workflows/authoritative-package-proof.yml` performs authoritative `sbuild` followed by `autopkgtest/QEMU` when a certified runner is available.
- Both authoritative workflows support controlled pre-merge `pull_request` label triggers and explicitly refuse fork PRs.
- `scripts/fetch-ubuntu-26.04-cloud-image.sh` verifies Ubuntu's signed released-image checksum metadata before accepting the base image.
- `scripts/install-actions-runner.sh` verifies the SHA-256 digest published in GitHub release metadata before installing the runner software.
- `scripts/provision-authoritative-runner-guest.sh` prepares the Ubuntu 26.04 KVM guest toolchain and records installed versions.
- `scripts/prepare-autopkgtest-qemu-image.sh` creates a real Resolute/amd64 QEMU test image and generates SHA-256/provenance at runtime.
- `scripts/seal-authoritative-runner-image.sh` removes registration/job state and resets clone identity before the image becomes a backing image.
- `scripts/run-kvm-jit-gate.sh` implements host-side overlay creation, JIT runner creation/injection, controlled PR gate triggering, result resolution, diagnostic export and cleanup.
