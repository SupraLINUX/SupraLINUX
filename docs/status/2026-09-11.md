## Decisions

- Ubuntu 26.04 LTS is the base platform.
- KDE upstream stable is authoritative for the desktop stack.
- Qt provider selection follows KDE's selected requirement profile.
- SupraLINUX remains a mutable `.deb`/APT/dpkg system.
- Repository workflows must use an explicit Ubuntu version rather than `ubuntu-latest`.
- Authoritative package builds will use clean sbuild environments on disposable self-hosted Ubuntu 26.04 VMs.
- Build graph results use `PASS`, `FAIL` and `BLOCKED`, with `BLOCKED` distinct from `FAIL`.

## Inference

Ubuntu Qt 6.10.2 is a strong reuse candidate for the current Plasma 6.7 profile because it matches the Qt 6.10 line selected by KDE. Version-line agreement and the hosted policy check are insufficient to claim full package/runtime compatibility.

## Verified bootstrap evidence

The repository-policy lane is currently **PASS** for commit `c3958f60ac7c03c8552548cbfaa9e202b2e1e2f3`.

What this proves:

- the repository invariants script executes successfully;
- the selected GitHub runner is actually Ubuntu 26.04;
- the current Ubuntu archive exposes a Qt package in the required 6.10 series;
- `ubuntu-latest` is not needed for the bootstrap lane.

What this does **not** prove:

- that the full Qt module set required by KDE is present and compatible;
- that KDE Frameworks, Plasma or Gear build successfully;
- that ABI/private-API consumers are compatible;
- that the self-hosted authoritative runner contract is satisfied;
- that any SupraLINUX package is ready for promotion.
