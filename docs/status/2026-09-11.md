## Decisions

- Ubuntu 26.04 LTS is the base platform; KDE upstream stable is authoritative for the desktop stack.
- Qt provider selection follows KDE's selected requirement profile.
- SupraLINUX remains a mutable `.deb`/APT/dpkg system.
- GitHub-hosted Ubuntu 26.04 is a **non-authoritative preflight lane**.
- Authoritative build/test execution occurs inside disposable self-hosted **KVM virtual machines running Ubuntu 26.04**.
- The authoritative runner VM uses a fresh `sbuild/unshare` environment for package builds.
- Authoritative package/system tests use `autopkgtest/QEMU` inside the KVM runner VM; nested KVM is part of the certification contract.
- Build artifacts and hashes are captured immediately after successful build gates, before later test gates.
- Build graph states are `PASS`, `FAIL` and `BLOCKED`; `BLOCKED` is distinct from `FAIL`.

## Inference

Ubuntu Qt 6.10.2 remains a strong reuse candidate for the current Plasma 6.7 profile, but version-line agreement is not a certification result.

Attempt 2 showed that `sbuild/unshare` works on the hosted Ubuntu 26.04 runner while `autopkgtest/unshare` failed at a separate testbed-infrastructure layer. Attempt 3 independently confirms the clean hosted `sbuild/unshare` path with preserved binary evidence.

The hosted PASS validates the package-build mechanics only. It does not reduce the requirement for a disposable KVM runner and nested QEMU/KVM system test before authoritative Phase 1 completion.

## Implementation now available

- `.github/workflows/runner-contract.yml` checks Ubuntu 26.04, KVM virtualization, `/dev/kvm`, QEMU/KVM capability, toolchain and prepared test image.
- `.github/workflows/authoritative-package-proof.yml` performs authoritative `sbuild` followed by `autopkgtest/QEMU` when a certified runner is available.
- `scripts/provision-authoritative-runner-guest.sh` prepares the actual Ubuntu 26.04 KVM guest toolchain and records installed versions.
- `scripts/prepare-autopkgtest-qemu-image.sh` creates a real Resolute/amd64 QEMU test image and generates its SHA-256/provenance at runtime.

## Pending certification

- provide a KVM/libvirt host capable of exposing nested KVM to a disposable Ubuntu 26.04 guest;
- boot/provision the authoritative guest image and create its real QEMU `autopkgtest` image;
- register each runner ephemerally with fresh GitHub credentials/JIT registration;
- pass `runner-contract.yml`;

- then proceed to repository publication/promotion and the real KDE metadata/DAG work.

## Blocked

The repository-side implementation can continue no further toward **authoritative** Phase 1 evidence without an actual KVM execution host. This is an infrastructure dependency, not a package failure. No authoritative PASS is claimed before that VM actually runs the workflows.
