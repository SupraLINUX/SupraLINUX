## Decisions

- Ubuntu 26.04 LTS is the base platform.
- KDE upstream stable is authoritative for the desktop stack.
- Qt provider selection follows KDE's selected requirement profile.
- SupraLINUX remains a mutable `.deb`/APT/dpkg system.
- Repository workflows must use an explicit Ubuntu version rather than `ubuntu-latest`.
- GitHub-hosted Ubuntu 26.04 is a **non-authoritative preflight lane**.
- Authoritative build/test execution occurs inside disposable self-hosted **KVM virtual machines running Ubuntu 26.04**.
- The authoritative runner VM uses a clean `sbuild/unshare` environment for package builds.
- Authoritative package/system tests use `autopkgtest/QEMU` inside the KVM runner VM; nested KVM is part of the certification contract.
- Build artifacts and hashes must be captured immediately after a successful build, before later test gates run.
- Build graph results use `PASS`, `FAIL` and `BLOCKED`, with `BLOCKED` distinct from `FAIL`.

## Inference

Ubuntu Qt 6.10.2 is a strong reuse candidate for the current Plasma 6.7 profile because it matches the Qt 6.10 line selected by KDE. Version-line agreement and the hosted policy check are insufficient to claim full package/runtime compatibility.

Attempt 1 points narrowly to schroot session/user integration on the GitHub-hosted runner rather than to the proof package or Ubuntu rootfs creation.

Attempt 2 demonstrates that `sbuild/unshare` is viable on the GitHub-hosted Ubuntu 26.04 image. Its later failure is specific to constructing the separate `autopkgtest/unshare` testbed and does not invalidate the already-completed binary build. The smoke test itself was never run, so no package-test PASS or FAIL is claimed from attempt 2.
