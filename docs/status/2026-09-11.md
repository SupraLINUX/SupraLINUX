## Decisions

- Ubuntu 26.04 LTS is platform authority; KDE upstream stable is desktop authority.
- Qt provider selection follows KDE's requirement profile.
- SupraLINUX remains mutable and `.deb`/APT/dpkg based.
- GitHub-hosted Ubuntu 26.04 is **non-authoritative preflight** only.
- Authoritative execution occurs inside disposable Ubuntu 26.04 **KVM VMs** using one-job repository-scoped JIT runners.
- Pre-merge self-hosted gates use controlled labels and reject fork PRs.
- Golden images are built from signed/verified released Ubuntu images, retain real provenance/hashes, are clone-cleaned offline, flattened/checked, and contain neither persistent GitHub credentials nor the temporary SupraLINUX build checkout.
- Host-local authoritative orchestration is serialized; queued/active authoritative workflows block new runner creation.
- JIT evidence is bound to one newly-created workflow run ID for the exact PR head SHA; ambiguous attribution fails.
- Authoritative builds use fresh `sbuild/unshare` isolation and preserve `.deb/.changes/.buildinfo` before runtime tests.
- Nested KVM is a runtime gate: a minimal QEMU process must initialize `-accel kvm -cpu host`.
- Authoritative `autopkgtest/QEMU` uses `scripts/qemu-kvm-required.sh` via `--qemu-command`, with explicit x86_64 architecture. The wrapper has no TCG fallback and its SHA-256 is evidence.
- Repository Policy syntax-checks all shell scripts and functionally tests the QEMU wrapper's argument forwarding/failure semantics.
- DAG states remain `PASS`, `FAIL`, `BLOCKED`; `BLOCKED` is never counted as `FAIL`.

## Inference

Ubuntu Qt 6.10.2 remains a strong reuse candidate for Plasma 6.7, but matching the version line is not certification.

The hosted package-build path is proven. Repository-side implementation now covers the intended Phase 1 chain from host preflight through verified source/golden images, exact-run-bound JIT execution, `sbuild`, runtime nested-KVM validation and deterministic KVM-only `autopkgtest/QEMU` invocation.

Repository-side syntax, semantic-policy and deterministic-wrapper behavior are now all validated. Those results do **not** establish actual nested KVM behavior on the intended host, real image hashes produced there, real runner-group authorization, or a real authoritative `autopkgtest` PASS.
