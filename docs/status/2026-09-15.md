## ECM closure scope incident

The same closure commit exposed an unrelated CI scope defect in the ECM lane. The old selector treated any change to `manifests/kde-dag.json` or `docs/kde-dag.md` as if it changed ECM build inputs, even though `scripts/run-kde-ecm-package-preflight.sh` does not consume either file.

ECM workflow run `35009710506`, job `104518322483`, therefore rebuilt `extra-cmake-modules 6.30.0-0supralinux3` unnecessarily. The run passed and produced artifact `10413246489`, SHA-256 `19f8ce8e17be9efab705df0a8974d89ef90ddcd06f5a9c53745f40ad227dcff4`.

Classification: `infrastructure-scope-selection`; `package_state_effect=none`. The artifact is not promoted, does not supersede retained ECM evidence and does not change the canonical package revision.

The first remediation commit `906d8be5094f04d03a01de035e73b6c65ea0a58a` correctly narrowed the pathspec but exposed a second selector-contract defect. The selector printed `run=false` yet returned status 0; the workflow consumes the exit status, so ECM run `35010423516`, job `104520693096`, entered `sbuild` even though the event delta contained no package-consumed ECM input.

Classification remains `infrastructure-scope-selection`; `package_state_effect=none`. This run is not authoritative package evidence and cannot supersede the retained ECM PASS.

Corrected selector contract: `0 = rebuild`, `1 = intentional skip`, any other status is an error. Rebuild scope remains limited to `packages/kde/extra-cmake-modules/*`, `scripts/run-kde-ecm-package-preflight.sh` and `.github/workflows/kde-ecm-package-preflight.yml`; DAG state/evidence, documentation, validators and selector-only edits must scope-skip.
