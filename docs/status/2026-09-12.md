Commit `c18c8dcd1934a5bba874e642ba9b14729d2e69df` attempted `kf6-attica 6.30.0-0supralinux1`.

- Repository Policy run `34705165935`: **PASS**;

- Attica workflow run: `34705165994`;
- result: **FAIL**;
- evidence artifact: `10300903114`;
- artifact SHA-256: `171cfe8553aba2af8f42a640ee5f50f82988005edbd104b737d93b639dc38300`;
- failure stage: `source-package`.

The failure happened before `sbuild`. `dpkg-buildpackage -S` invoked `debian/rules clean` on the hosted runner, and debhelper attempted to load `dh-sequence-kf6`. That helper is a real Build-Depends item and belongs in the clean sbuild environment; installing it on the host merely to assemble the `.dsc` would blur the clean-build boundary.

This is recorded as a real Attica FAIL because the node was actually attempted. It is not a Qt-provider, ECM-predecessor, KDE-upstream or ABI failure.

## Attica remediation candidate

Candidate package revision: `6.30.0-0supralinux2`.

The source package is now assembled with `dpkg-source -b` using the package's explicit `3.0 (quilt)` source format. This creates the `.dsc` and Debian tarball without executing `debian/rules`; actual package Build-Depends are then installed and exercised only by the fresh Resolute `sbuild` root.

The first failed revision remains in `debian/changelog` and its workflow/artifact evidence is retained.

## Test-scope boundary

Hosted package PASS states are **hosted clean-package DAG preflights**, not final release certification. They verify KDE source integrity, Debian package creation, clean `sbuild/unshare`, package policy, compatibility/ABI checks where applicable, downstream consumption and retained artifacts. They do not replace the authoritative nested-KVM release gate.
