## ECM DAG root — first real attempt

Commit `99b95b1c0897ed20af6c8add7aa1620ef1795019` introduced the ECM 6.30.0 package node and attempted package revision `6.30.0-0supralinux1`.

Repository Policy run `34689672651`: **PASS**, including `Validate KDE DAG invariants`.

ECM workflow run `34689672632`: **FAIL**.

Retained failure evidence:

- artifact ID: `10296512341`;
- artifact digest: `sha256:d47ac7361106ceb5f04729c1a3dcb4103b30255684e5b3f53b833edd6d4f6558`;
- upstream ECM source SHA-256 verification: PASS;
- Debian source-package creation: PASS;
- clean build environment setup: PASS;
- CMake configure: PASS;
- Ninja build: PASS;
- failure stage: `dh_auto_test`.

Root cause: the package-preflight CMake profile intentionally used `BUILD_TESTING=OFF`, so no Ninja `test` target existed, while debhelper still ran `dh_auto_test` and invoked `ninja test`. Ninja reported an unknown `test` target. This is a packaging-integration FAIL, not an ECM source, compiler, Qt or dependency failure.

A separate efficiency problem was also observed: the script generated `resolute-amd64-kde-ecm.tar.gz`, but `sbuild/unshare` looked for `${HOME}/.cache/sbuild/resolute-amd64.tar` and therefore generated another rootfs.

## Remediation pending validation

The remediation is versioned as `6.30.0-0supralinux2` rather than rebuilding different packaging under the same Debian version.

Changes prepared:

- explicit `override_dh_auto_test` for the `BUILD_TESTING=OFF` package-preflight profile;
- mandatory post-build downstream consumer smoke retained;
- reusable mmdebstrap rootfs aligned to `${HOME}/.cache/sbuild/resolute-amd64.tar`, tar format and the sbuild-compatible `output/mknod` skip;
- rootfs, source and package artifact hashes remain retained.

The manifest intentionally remains `FAIL` until this remediation is actually attempted and passes. No Tier 1 Framework node is attempted while ECM lacks a PASS artifact.
