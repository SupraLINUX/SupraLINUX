## Attica CI event-delta scope

The package-build and packaging-reference workflows now evaluate the exact `before..after` commit range for `pull_request/synchronize`. Their expensive steps are conditional on actual build/capture inputs, not on the PR-wide changed-file set relative to `main`.

Expected behavior for a documentation/evidence-only synchronization is: scope step PASS, package/reference work skipped intentionally, no new package/reference artifact, and no change to Attica's existing PASS evidence. Repository Policy enforces the scope configuration; CI run evidence is retained once this behavior is exercised on a documentation-only commit.

## Test-scope boundary

The ECM and Attica PASS states are **hosted clean-package DAG preflights**. They verify source integrity, clean `sbuild/unshare`, package policy, tests, ABI/contract checks where applicable, consumer validation and retained artifacts. They do not replace the authoritative nested-KVM release gate or later system/runtime compatibility gates.
