# Build y repositorios
Fuentes: [Arch Archive](https://wiki.archlinux.org/title/Arch_Linux_Archive), [clean chroot](https://wiki.archlinux.org/title/DeveloperWiki:Building_in_a_clean_chroot), [Arch build system](https://wiki.archlinux.org/title/Arch_Build_System), [security tracker](https://security.archlinux.org/), [Arch packaging standards](https://wiki.archlinux.org/title/Arch_package_guidelines).
Congelar snapshot de core/extra y multilib cuando habilitado, pin de fecha/DB hash, versiones, firmas, fuentes, toolchain y repos propios. Mirror propio de artefactos autorizados para disponibilidad, verificar licencias/redistribución y proveer fuentes correspondientes. No depender indefinidamente de retención upstream. PKGBUILD y devtools para paquetes propios, builds limpios, lock de dependencias, reproducibilidad comprobada (no prometer bit-identical). Build de imagen desde manifiesto, SBOM, hashes, metadata de seguridad, firmas y provenance. Claves offline/release separadas de CI, rotación y revocación; proteger firma de contribuciones no confiables. CI VM y hardware para kernel/graphics, pruebas visuales e IA del escritorio, QEMU/KVM boot y rollback. Canales dev/testing/stable, promoción de la misma imagen probada, no recompilar al promover. Seguridad: seguir advisories Arch y upstream, escanear CVE, preparar conjunto nuevo coherente o backport reconstruido y validado; no congelar vulnerabilidades por calendario. Objetivo de respuesta a críticos por definir con capacidad real, no prometer SLA. Rollout gradual, pausa y rollback, comunicación de versiones afectadas. Arch no soporta partial upgrades; capas construidas contra snapshot de destino. Sin publicación estable ni migración sin autorización.

## Profundización
[Entrega y releases](DELIVERY_SECURITY.md) define snapshot lock, staging, firma, cadena de promoción, canales, CVE, retención, metadata verificable, mirror y deltas. Arch Archive no mezclar con mirrors rolling. Candidatos TUF y formatos SBOM SPDX/CycloneDX; elegir herramienta tras prueba. No congelar correcciones críticas ni prometer SLA sin recursos.
