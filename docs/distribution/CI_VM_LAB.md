# CI y laboratorio de VM — propuesta 2026-11-25
GitHub-hosted ubuntu-24.04 en repos públicos como baseline: 4 vCPU/16 GB RAM/14 GB SSD anunciados; capacidad real y /dev/kvm variables. [GitHub runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), [nested virtualization](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners). No garantía oficial de nested virtualization. Probar apertura efectiva y query-kvm. QEMU TCG fallback para smoke funcional; no contar como PASS KVM ni benchmark. Runner efímero, sin secretos productivos.
[Probe](../../tools/system-lab/kvm_probe.py): guest sintético mínimo, QMP query-kvm y screendump PPM, reporte JSON, logs; workflow [kvm-probe](../../.github/workflows/kvm-probe.yml), artefactos 7 días. No prueba una ISO real, UEFI, atomicidad ni GPU. Captura debe inspeccionarse por separado.
## Diseño siguiente
QEMU/KVM + OVMF, disco qcow2 base inmutable y overlay descartable por caso, NVRAM UEFI por VM, red aislada según prueba, serial logs, QMP local Unix socket, guest agent/SSH de laboratorio o canal virtio-serial para estado tipado, eventos de readiness en vez de sleep para pruebas reales. Capturas por QMP o in-guest autorizado, no capturar escritorio real del mantenedor. [QMP](https://www.qemu.org/docs/master/interop/qemu-qmp-ref.html) [Virtio GPU](https://www.qemu.org/docs/master/system/devices/virtio/virtio-gpu.html). KVM acelera CPU, no garantiza GPU real. Virtio 2D + Mesa llvmpipe para visuales deterministas; probar virgl aparte, si screendump no soporta scanout usar captura del guest. SupraDesktop nested/headless tests sin VM para cada commit, integración en VM al candidato.
Jobs cortos en PR, instalación/update/rollback/fault injection en jobs separados o nightly cuando implementados, no automatización programada ahora. Guardar versiones, hashes, reporte PASS/FAIL/BLOCKED, capturas inicial/final/fallo, serial/journal redactados y métricas. Artefactos de corto plazo, imágenes grandes fuera de Git y no duplicadas por cada test. Control de timeout, disco y concurrencia. No publicar secretos ni ejecutar PR no confiables en runner personal; runner GPU/KVM dedicado y aislado, solo código revisado. No activar self-hosted en máquina del mantenedor por defecto.
