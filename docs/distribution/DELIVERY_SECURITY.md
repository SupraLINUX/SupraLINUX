# Entrega de imágenes, repositorios, CVE y canales
Fuentes: [Arch Archive](https://wiki.archlinux.org/title/Arch_Linux_Archive), [Arch security tracker](https://security.archlinux.org/), [TUF metadata](https://theupdateframework.io/docs/metadata/), [Btrfs send](https://btrfs.readthedocs.io/en/latest/btrfs-send.html), [RAUC adaptive updates](https://rauc.readthedocs.io/en/stable/advanced.html).
## Snapshot coherente y retención
Pin fecha UTC, repo DB hashes, package NEVRA-equivalente Arch (name, epoch/pkgver/pkgrel/arch), signature/source digest y toolchain; repos core/extra/multilib mismos epoch, no fallback a rolling. Conservar closure necesaria para imágenes, símbolos/debug si autorizado, PKGBUILD/patches/fuentes, manifiestos y SBOM por build, licencias y obligaciones de redistribución. No espejar todo AUR ni publicar binarios propietarios sin permiso. Build de paquetes y root limpio, validar dependencias y firmas, no prometer reproducibilidad bit-a-bit sin comparación. Manifest firmado e inmutable, ID por digest, cache y mirrors verificables. Artefactos grandes fuera de Git, almacenamiento HTTP/CDN/object storage candidato, Range/resume, límites, métricas de coste y disponibilidad. Política de retención por releases soportadas, rollback y recovery, no depender solo de upstream histórico.
## Deltas
Primero full image comprimida zstd y descarga reanudable; baseline tamaños, bytes y tiempos medidos. Btrfs incremental send requiere parent snapshot exacto inmutable, no asumir una capa local coincide; distribuir delta solo desde digest base compatible y verificar resultado. RAUC adaptive block reuse reduce transferencia con HTTP Range; no aporta automáticamente layering. Evaluar chunking/casync y delta por artefacto solo si evidencia de coste; fallback full obligatorio si base no coincide o falla. Nunca aplicar delta sobre sistema activo. Verificar hash/firmas del destino, límites de espacio y recuperación tras corte. No prometer porcentaje de ahorro.
## Seguridad y promoción
Inventariar SBOM OS y paquetes propios/transitivos, correlacionar CVE con versión y backports reales, Arch tracker + upstream advisories, revisar explotabilidad y exposición; no depender de una sola fuente ni confundir CVSS con impacto. Priorizar críticos explotados y componentes expuestos; crear snapshot nuevo coherente o reconstruir backport con closure y pruebas, no partial upgrade. SLA solo al medir capacidad del equipo. Flatpak/AppImage/AUR tienen lifecycle distinto; comunicar límites y actualización por proveedor. Mantener ruta limpia si capa bloquea parche crítico, no retirar capa sin consentimiento.
Dev: cambios y artefactos experimentales. Testing: mismo digest candidato, VM y hardware, gates de regresión/upgrade/rollback. Stable: promover exacto digest firmado tras aprobación; manifest de canal distinto, no rebuild. Pausar rollout, alertar afectación, revocar artefacto inseguro con ruta recuperable, conservar registro de release y fuentes. Canales opt-in, cambio de canal preview con capas/datos; rollback deliberado no igual a downgrade remoto. TUF metadata expiración y versiones, recuperación offline de releases conocidas y política separada. Telemetría no obligatoria; feedback voluntario y pruebas propias.
