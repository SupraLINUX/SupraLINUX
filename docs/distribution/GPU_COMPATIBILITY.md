# GPU, CUDA y gaming
Fuentes: [NVIDIA Arch transition](https://archlinux.org/news/nvidia-590-driver-drops-pascal-support-main-packages-switch-to-open-kernel-modules/), [CUDA compatibility](https://docs.nvidia.com/deploy/cuda-compatibility/), [NVIDIA CDI](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/cdi-support.html), [Flatpak extensions](https://docs.flatpak.org/en/latest/extension.html).
NVIDIA kernel module y userspace deben concordar por imagen; open modules para generaciones soportadas, rama legacy o Nouveau evaluar para Pascal, no afirmar soporte sin kernel/driver real. Intel/AMD Mesa/firmware/DRM, Vulkan, explicit sync, VA-API/video y multi-GPU. CUDA runtime en contenedor puede ser independiente del toolkit host, requiere driver compatible y dispositivo autorizado; usar CDI candidato para Podman, verificar tras cambio de driver y rollback. No desactivar compat checks para ocultar incompatibilidad. Flatpak GL extension según versión driver; preflight disponibilidad de runtime y 32-bit cuando corresponda, fallback y error claro. Steam/Proton: multilib en host si proveedor nativo; Flatpak tiene runtime propio, no mezclar arbitrariamente. Probar native/Flatpak juegos, XWayland/Wayland, audio, controller, suspend, fullscreen, VRR, high refresh, multi-output y overlays. No garantizar todos juegos/anti-cheat.
Presupuesto GPU P17: presión real bajo IA local, cachés purgables, menor resolución de blur, desactivar óptica cara, fallback sólido; histéresis y recuperación; no cerrar apps ni tocar protecciones térmicas. No garantizar continuidad si driver falla o memoria completamente agotada. Medir p95/p99, VRAM propia/importada, dropped frames, latencia y estabilidad bajo fixture controlado. RTX3090 caso de prueba, no hardware obligatorio.
