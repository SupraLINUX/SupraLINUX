# Phase 1 — package-build proof

Status: **implementation in progress**  
Last reviewed: **2026-09-11**

## Purpose

This lane proves the mechanics required before SupraLINUX starts building the real KDE dependency graph.

The proof package is intentionally trivial. Its value is the build and evidence path, not the payload.

## Package

`packages/supralinux-build-test`

It is a native Debian source package with:

- `debhelper-compat (= 13)`;
- an architecture-independent binary package;
- one installed command and one data marker;
- a superficial `autopkgtest` smoke test.

The package is not part of the intended desktop product.

## Hosted proof lane

`.github/workflows/package-build-proof.yml` runs on explicit `ubuntu-26.04` and:

1. verifies the host is Ubuntu 26.04;
2. installs the package-build/test tooling;
3. creates a source package;
4. creates a fresh Ubuntu 26.04 (`resolute`) sbuild chroot;
5. performs the package build through `sbuild`;
6. requires `.deb`, `.changes` and `.buildinfo` outputs;
7. runs `autopkgtest` against the built package;
8. records SHA-256 values generated by the actual run;
9. uploads logs, package artifacts and a machine-readable result record.

The result record uses `PASS` or `FAIL` because this node is actually attempted. `BLOCKED` is reserved for DAG nodes that are not attempted because a dependency failed or is unavailable.

## Authority boundary

This hosted job is **non-authoritative**. GitHub currently describes its Ubuntu 26.04 hosted image as public preview. A successful hosted proof validates the implementation path, but it does not substitute for the disposable self-hosted Ubuntu 26.04 VM contract defined in `docs/runners/ubuntu-26.04.md`.

The same package/evidence contract should later be executed on the authoritative runner class without weakening the gates.

## Evidence

No run result is claimed in this document until the workflow has actually executed. Run IDs, artifact hashes and PASS/FAIL state must be copied from real CI evidence only.
