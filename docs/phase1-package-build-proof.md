# Phase 1 — package-build proof

Status: **implementation in progress**  
Last reviewed: **2026-09-11**

## Purpose

This lane proves the mechanics required before SupraLINUX starts building the real KDE dependency graph.

The proof package is intentionally trivial. Its value is the build and evidence path, not the payload.

## Package

`packages/supralinux-build-test`

It is a native Debian source package with:

- `debhelper-compat (= 13)`;
- an architecture-independent binary package;
- one installed command and one data marker;
- a superficial `autopkgtest` smoke test.

The package is not part of the intended desktop product.

## Hosted proof lane

`.github/workflows/package-build-proof.yml` runs on explicit `ubuntu-26.04` and:

1. verifies the host is Ubuntu 26.04;
2. installs package-build/test tooling;
3. verifies unprivileged user namespaces and subordinate UID/GID mappings;
4. creates a source package;
5. creates a fresh Ubuntu 26.04 (`resolute`) `buildd` rootfs with `mmdebstrap`;
6. performs the package build through `sbuild --chroot-mode=unshare`;
7. requires `.deb`, `.changes` and `.buildinfo` outputs;
8. runs `autopkgtest` in a separate `unshare` testbed using the same clean rootfs baseline;
9. records SHA-256 values generated by the actual run;
10. uploads logs, package artifacts and a machine-readable result record.

The result record uses `PASS` or `FAIL` because this node is actually attempted. `BLOCKED` is reserved for DAG nodes that are not attempted because a dependency failed or is unavailable.

## Why `unshare`

The first implementation used the legacy `schroot` backend. Real run **34610526616** successfully created the `resolute-amd64-sbuild` chroot but `sbuild` then failed with:

`E: Error creating chroot session: skipping supralinux-build-test`

That run is a real **FAIL**, not `BLOCKED`. Its evidence artifact is **10268843020**, whose GitHub artifact ZIP digest is:

`sha256:0e17798003bdb563d0fd99a299e8d4b316fd9ffbd2467e0faf70019687c95450`

The artifact's `result.json` records `state: FAIL`, `exit_code: 1`, and `authoritative: false`. Source package creation and chroot bootstrap both completed before the session failure.

Ubuntu 26.04 ships `sbuild 0.91.2ubuntu3`; its documentation supports the `unshare` backend, which uses Linux user namespaces and avoids the `schroot` session/group mechanism that failed in the hosted runner. SupraLINUX therefore uses `unshare` for this clean package-build proof while keeping the higher-level architecture unchanged: builds still happen inside isolated, freshly provisioned `sbuild` environments, and authoritative builds still belong on disposable SupraLINUX runner VMs.

## Authority boundary

This hosted job is **non-authoritative**. GitHub currently describes its Ubuntu 26.04 hosted image as public preview. A successful hosted proof validates the implementation path, but it does not substitute for the disposable self-hosted Ubuntu 26.04 VM contract defined in `docs/runners/ubuntu-26.04.md`.

The same package/evidence contract should later be executed on the authoritative runner class without weakening the gates.
